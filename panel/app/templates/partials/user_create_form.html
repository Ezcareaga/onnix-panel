{# Formulario de alta de usuario, con el error al lado del campo que lo causo. El patron viene de users_create_agent.html, que era el unico formulario del panel que lo hacia bien y que estaba muerto: su GET redirige con 301 desde hace fases. Se rescata aca, que es el alta que la administradora usa de verdad. Antes el error de este formulario volvia dentro de users_table.html y se swapeaba en #settings-users-table — o sea, DEBAJO del abierto, que inertiza el resto de la pagina. El usuario apretaba "Guardar", no pasaba nada visible, y el mensaje estaba tapado por el modal. Ahora users.py retarget-ea la respuesta de error a este mismo form (HX-Retarget + HX-Reswap: outerHTML), asi que el 422 se pinta donde el usuario esta mirando. El camino de exito no cambia: sigue devolviendo la tabla al #settings-users-table. Contexto: `errors` (dict campo -> mensaje) y `form` (valores tipeados). Los dos opcionales: en el alta limpia no vienen. #} {% set errors = errors | default({}) %} {% set form = form | default({}) %} {# errors/form van por parametro: un macro no deberia depender de que el contexto del include tenga un nombre suelto. #} {% macro campo(errors, form, nombre, etiqueta, tipo='text', requerido=false, placeholder='', autocomplete='', extra='') %} {%- set err = errors.get(nombre) -%} {% if err %}

{{ err }}

{% endif %} {% endmacro %}
